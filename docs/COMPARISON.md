# Agent memory approaches

Documentation reviewed on **November 12, 2026**. The comparison uses each project's official documentation to describe published capabilities and architectural choices.

Agent Shadow Brain 7.1.4 combines local project memory, explicit reviews, recorded relationships, bounded task briefs, and an activity journal. Project Kit observes stack markers, saves supplied knowledge, and previews a task-specific skill before writing it to the selected project. Its adaptive profile uses lexical retrieval with coding-oriented identifiers, inspectable ranking signals, and one-hop expansion over recorded links. Reported outcomes can adjust matching candidates in the same project. [Project Kit](PROJECT_KIT.md) · [Context Lab](CONTEXT_LAB.md) · [Reported outcomes](LEARNING.md)

| Approach | Published capability | Practical tradeoff |
| --- | --- | --- |
| **Mem0 Platform** | Native entity links connect memories that mention shared entities. Platform retrieval blends vector similarity, BM25, and graph signals. Its documented graph runs inside the platform. | Automatic semantic and entity recall serves applications that need wider associations. Shadow Brain relies on local lexical matches and explicitly recorded project links, so reviewers can trace how each linked record entered a brief. [Mem0 Graph Memory](https://docs.mem0.ai/platform/features/graph-memory) |
| **Letta** | Current documentation describes a Git-backed memory filesystem shared across agent conversations and background memory maintenance through dreaming. | The agent lifecycle and its memory live together. Shadow Brain supplies context and review tools to existing coding clients. Its learning signal uses explicit project outcomes and can be inspected, paused, or removed. [Letta memory and dreaming](https://docs.letta.com/configuration/memory) |
| **Graphiti** | Builds temporal knowledge graphs from episodes. Facts carry validity information, and retrieval combines semantic, keyword, and graph search. The open-source framework documents graph backends and model-service setup. | Temporal validity and episode provenance support evolving fact histories. Shadow Brain records manual supersession, contradictions, and review state in a small local store. [Graphiti source and documentation](https://github.com/getzep/graphiti) |
| **Claude-Mem** | Documents hook-based capture, a local viewer, and progressive disclosure from search results to timelines and full observations. Its current documentation covers multiple host integrations. | An observation capture workflow serves session-history recall. Shadow Brain's current workspace focuses on saved project decisions, explicit curation, and selected context. Its live journal tracks bounded activity metadata separately from memory content. [Claude-Mem source](https://github.com/thedotmack/claude-mem) · [Progressive disclosure](https://docs.claude-mem.ai/progressive-disclosure) |
| **Qdrant** | Its Query API combines dense and sparse retrieval stages, fusion, and rescoring. The documentation also covers payload filtering and multitenancy. | These capabilities give developers building blocks for a retrieval service. Shadow Brain bundles a coding-memory workflow over a local JSON store with a curated ranking pipeline and a workspace. [Qdrant hybrid queries](https://qdrant.tech/documentation/search/hybrid-queries/) · [Multitenancy](https://qdrant.tech/documentation/manage-data/multitenancy/) |
| **MCP reference memory server** | The reference server stores a graph of entities, observations, and directed relations with MCP tools for reading and updating it. | This is a small general graph API. Shadow Brain adds project context assembly, review state, ranking explanations, and evidence inspection around coding memories. [Reference memory-server source](https://github.com/modelcontextprotocol/servers/tree/main/src/memory) |

## What the local evaluation establishes

Both Shadow Brain profiles ran against the same 14 author-generated cases. Adaptive passed all 14 and Legacy passed 6. The differences include exact-term matching, technical identifier variants, relevant excerpts, duplicate handling, and recorded one-hop retrieval. The evidence applies to the named local retrieval cases. [Paired evaluation](evaluation/CONTEXT_EVALUATION_v7.1.4.md)

The adaptive implementation borrows term-frequency saturation and document-length normalization from BM25-style ranking. The local report separates selected-record relevance, passage visibility, scope, budgets, and no-match behavior. LongMemEval describes a broader benchmark for long-term conversational memory. [Lucene BM25Similarity](https://lucene.apache.org/core/10_5_2/core/org/apache/lucene/search/similarities/BM25Similarity.html) · [LongMemEval paper](https://arxiv.org/abs/2410.10813)

Run `npm run build` and `npm run test:context-eval` from a source checkout to reproduce the local cases.
